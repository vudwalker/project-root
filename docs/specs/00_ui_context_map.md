# UIコンテキスト対応表

この文書は、スタッフ用UIと管理者用UIの混同を防ぐための最上位の早見表である。

## 1. 一人の人物と複数権限

一人の人物は一つの`users.id`を持つ。

権限は独立して付与する。

```text
users.id = 15
├── role: staff
└── role: shift_manager
```

`shift_manager`は`staff`を暗黙に含まない。

## 2. UIの対応

| 項目 | スタッフ用UI | 管理者用UI |
|---|---|---|
| URL | `/staff/**` | `/admin/**` |
| 主な利用権限 | `staff` | `shift_manager`, `system_admin` |
| View | `resources/views/staff/**` | `resources/views/admin/**` |
| データ | `published_shifts` | `shifts` |
| 状態 | 最後に配布された公開版 | 最新の下書き |
| 操作 | 閲覧専用 | 編集、確認、配布 |
| 主対象端末 | スマートフォン | PC |
| UI方針 | 完成済みUIを維持 | 既存Excel・参考画像を忠実に再現 |

## 3. 正式な画面名

### スタッフ用

- スタッフ用・マイシフト画面
- スタッフ用・店舗公開シフト画面

### 管理者用

- 管理者用・店舗別シフト編集画面
- 管理者用・スタッフ別シフト確認画面

「スタッフ別画面」「店舗別画面」だけの呼称は禁止する。

## 4. 同じユーザーが両方の権限を持つ場合

- `/staff`ではスタッフ用UIを表示する。
- `/admin`では管理者用UIを表示する。
- UIを一つに統合しない。
- 管理者用ボタンをスタッフ用画面へ追加しない。
- スタッフ用ナビゲーションを管理者用画面へ流用しない。

## 5. 店舗との関係

- `store_user`：スタッフとしての所属
- `store_shift_manager`：管理者としての担当

同じユーザーが両方へ登録されても、意味は別である。

スタッフ本人の氏名、メールアドレス、在籍状態、ロール、パスワードは、
今後追加する組織単位のスタッフ管理画面で管理する。

店舗管理画面は`users`を作成・更新せず、同一組織に登録済みの
`staff`を検索し、`store_user`による店舗所属だけを追加・解除する。

## 6. 実装停止条件

以下のいずれかが発生した場合は実装を止めて報告する。

- 管理者用実装で`resources/views/staff/**`を変更する必要がある。
- `/staff`で`shifts`を表示しようとしている。
- `/admin`で`published_shifts`を編集しようとしている。
- 同じBladeを権限条件で両UIに使用しようとしている。
- 「スタッフ別」という名称だけで画面を判断している。
- 管理画面の参考画像をスタッフ用UIへ適用している。
