# Codex実装依頼プロンプト集

## 0. 使用方法

管理者用UIの実装は、一つの巨大な依頼で完了させない。

以下の順に、各段階の完了報告と画面確認を行ってから次へ進む。

1. 既存実装の調査
2. 静的な管理者用UIの再現
3. 下書きデータと編集ロジックの接続
4. 配布・整合性・回帰テスト

スタッフ用UIと管理者用UIを混同した場合は、その段階の実装を不採用とする。

Git commitは行わせない。

---

# プロンプト1：変更禁止の事前調査

```text
Laravel製シフト管理システムの既存実装を調査してください。

この段階では、コード、設定、仕様書、画像を一切変更しないでください。

最初に必ず以下を読んでください。

- AGENTS.md
- docs/specs/01_requirements.md
- docs/specs/02_database.md
- docs/specs/03_staff_ui.md
- docs/specs/04_admin_ui.md
- docs/specs/images/ 配下の全参考画像

最重要事項：スタッフ用UIと管理者用UIは完全に別の画面領域です。

スタッフ用UI：
- /staff 配下
- resources/views/staff/ 配下
- 公開済み published_shifts の閲覧専用
- スマートフォン中心
- 既に完成しているUI

管理者用UI：
- /admin 配下
- resources/views/admin/ 配下
- 下書き shifts の編集・確認・配布
- PC中心
- 既存Excelを再現した高密度な表

同一ユーザーが staff と shift_manager の両方を持つ場合でも、UIを統合しません。
同じ users.id を使うことと、同じ画面を使うことを混同しないでください。

以下を調査し、コードを変更せず報告してください。

1. /staff と /admin のルート一覧
2. スタッフ用・管理者用のController一覧
3. スタッフ用・管理者用のBlade一覧
4. スタッフ用・管理者用のCSS・JavaScript一覧
5. published_shifts を読む処理
6. shifts を読む・更新する処理
7. 現在、両UIを混同している箇所
8. 管理者用実装のために再利用可能なロジック
9. 管理者用UIだけで作り直すべきファイル
10. スタッフ用UIへ影響する危険がある変更
11. 参考画像と現在の管理者用UIの視覚的差分
12. テストの現状

「スタッフ別画面」という名称だけで分類せず、ルート、データ種別、操作目的で判定してください。

報告後、私の承認を待ってください。
Git commitは行わないでください。
```

# プロンプト2：静的な管理者用UIだけを再現

```text
前段階の調査結果に基づき、管理者用UIの静的表示を実装してください。

この段階では、保存API、自動保存、配布処理、DB更新処理へ接続しないでください。
ダミーデータまたは既存データの読み取りだけで見た目を完成させます。

最重要事項：
- /staff 配下を変更しない
- resources/views/staff/** を変更しない
- スタッフ用CSS・JavaScriptを変更しない
- 管理者用UIをスタッフ用UIへ寄せない
- 一般的なカード型管理画面へ再設計しない

再現対象：

管理者用・スタッフ別シフト確認画面
- docs/specs/images/kanri_staffbetsu.png
- docs/specs/images/kanri_staffbetsu_ng.png

管理者用・店舗別シフト編集画面
- docs/specs/images/kanri_tenpobetsu.png
- docs/specs/images/kanri_tenpobetsu_ng.png

通常画像とNG画像は別画面ではなく、同じ画面の状態差です。

参考画像から以下を項目別に再現してください。

- 画面全体の背景
- 上部タイトルと対象年月
- 画面切り替え操作
- 店舗切り替え操作
- 表の開始位置
- 表の列数・列順
- スタッフ名列
- 日付・曜日列
- 月間計の列
- 行高
- 列幅
- 文字サイズ
- 罫線
- セル内の情報密度
- 土日祝の表示
- 固定ヘッダー
- 固定列
- 横・縦スクロール
- シフトコード選択ボタン
- 保存状態表示の位置
- 配布状態・配布ボタンの位置
- NG時の警告対象と警告表示

独自のサイドバー、カード、ダッシュボード、広い余白、装飾的アイコンを追加しないでください。

実装後はブラウザで画面を表示し、参考画像と比較してください。
「再現した」とだけ報告せず、次の形式で報告してください。

- 一致した項目
- 残っている視覚的差分
- 変更ファイル
- スタッフ用ファイルを変更していないこと
- 保存・配布ロジックへ未接続であること
- 実行した表示確認

私がUIを承認するまで、ロジック接続へ進まないでください。
Git commitは行わないでください。
```

# プロンプト3：管理者用UIへロジックを接続

```text
承認済みの管理者用静的UIへ、既存または仕様どおりの管理ロジックを接続してください。

承認済みのHTML構造と見た目を大きく変更しないでください。

管理者用・店舗別シフト編集画面：
- 最新の下書き shifts を表示
- シフト追加
- 個別削除
- 同一セルの複数シフト
- sequence順表示
- entry_uuidによる追加の冪等性
- 500〜1000ms程度のdebounce
- 自動保存
- 保存待ち、保存中、保存済み、保存失敗、競合の表示
- 担当店舗のサーバー側認可

管理者用・スタッフ別シフト確認画面：
- 閲覧専用
- 選択担当店舗へ有効な所属があるスタッフを対象
- 対象スタッフの全店舗の下書きを横断表示
- 担当外店舗は閲覧専用
- 編集UI、自動保存UIを設けない

最重要の整合性要件：

画面上の行番号、列番号、配列添字、表示順序をシフトの識別子にしないでください。

最低限、以下で対応付けてください。

- user_id
- store_id
- shift_date
- shift_id または entry_uuid
- sequence

DOMには必要に応じて以下を持たせてください。

- data-user-id
- data-store-id
- data-shift-date
- data-shift-id
- data-entry-uuid
- data-sequence

自動保存ではセル位置から対象を推測せず、識別情報を明示して送信してください。
サーバー側でも、送信されたshiftが指定ユーザー・店舗・日付に属することと、操作者の権限を再検証してください。

店舗別画面とスタッフ別画面は別のシフトデータを保存せず、同じ下書きを異なる軸で投影してください。

- 店舗別：store_id → user_id → shift_date → sequence
- スタッフ別：user_id → shift_date → store_id → sequence

禁止事項：
- resources/views/staff/** の変更
- スタッフ用CSS・JavaScriptの変更
- /staffで下書きを表示
- 管理者用Bladeをスタッフ用画面へ流用
- スタッフ名や店舗名をデータキーに使用
- 古い非同期レスポンスで新しい入力を上書き
- 月切り替え後に前月のレスポンスを現在月へ反映

実装後は、変更ファイル、認可方法、自動保存の識別キー、競合対策、実行テストを報告してください。
Git commitは行わないでください。
```

# プロンプト4：配布・境界・回帰テスト

```text
管理者用UIとスタッフ用UIの境界、下書きと公開版の境界、画面間のシフト整合性を検証してください。

必要な不具合修正は行ってよいですが、大規模なUI変更は行わないでください。

必須テスト：

1. staffだけのユーザーは/adminへアクセスできない
2. shift_managerだけのユーザーは/staffへアクセスできない
3. staffとshift_managerの両方を持つ同一users.idは/staffと/adminの両方へアクセスできる
4. 両方の権限を持っていても/staffではスタッフ用UIだけが表示される
5. 両方の権限を持っていても/adminでは管理者用UIだけが表示される
6. /staffはpublished_shiftsだけを表示する
7. /adminは下書きshiftsを表示する
8. 配布前の下書き変更は/staffへ反映されない
9. 配布後は同じuser_id、store_id、shift_date、時刻、sequenceで/staffへ反映される
10. 店舗別管理画面とスタッフ別管理画面で同じ下書きが同じ対象へ表示される
11. スタッフの並び順を変えてもシフトが別スタッフへ移動しない
12. 同姓同名でもuser_idで区別できる
13. 28日、29日、30日、31日の月で列ずれがない
14. 同一日の複数シフトをsequence順に表示する
15. 1件削除しても別スタッフ・別日・別店舗のシフトへ影響しない
16. 不正なshift_idとuser_id/store_id/shift_dateの組み合わせを拒否する
17. shift_managerが担当外店舗を編集できない
18. 古い自動保存レスポンスが新しい入力を上書きしない
19. 管理者用実装でスタッフ用UIのスクロール、レイアウト、レスポンシブ表示が変わっていない
20. 管理者用画面が参考画像の構造を維持している

テストでは件数だけでなく、user_id、store_id、shift_date、shift_id、entry_uuid、sequence、シフトコード、開始・終了時刻を具体的に検証してください。

最後に以下を報告してください。

- 実行したコマンド
- 成功・失敗したテスト
- 修正した不具合
- /staffと/adminの分離方法
- published_shiftsとshiftsの分離方法
- 画面間整合性の確認結果
- スタッフ用UIに生じた差分の有無
- 未解決事項
- git status
- git diff --stat

Git commitは行わないでください。
```

# 緊急停止プロンプト

Codexが再びUIを混同した場合は、次を使用する。

```text
作業を停止してください。これ以上コードを変更しないでください。

現在の差分から、以下を一覧化してください。

- /staffへ加えた変更
- /adminへ加えた変更
- スタッフ用Blade・CSS・JavaScriptへの変更
- published_shiftsとshiftsを混同している処理
- スタッフ用UIと管理者用UIで共通化したファイル
- 参考画像と異なる独自UI
- 元に戻すべき変更
- 残してよいバックエンドロジック

まだgit restore、git clean、git stash、git commitは実行しないでください。
報告後、私の指示を待ってください。
```
